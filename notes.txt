Async & await 
--------------

How Fetch works?
----------------

    formatted data

-> so here until fetch it is run directly at call stack first once the await fetch came then the code move to network subsystem and wait there until the fetch got the data 
    then after it moves to microtask queue and event loop will place the rest of the function in call stack 


Async vs promise
-----------------
async and await is just syntactical sugar that is it because it uses promise.then and catch only 
-> async avoid promise chaining ,we do not want to write .then.then like that 


The suspended part (continuation) is not in the call stack anymore. Instead, it’s kept in the Promise’s internal reaction queue.

When p eventually resolves, the JS engine schedules the continuation (the rest of the function after the await) as a microtask in the microtask queue.

The event loop will then take it out of the microtask queue and push it back to the call stack for execution.

So the suspended code is essentially stored in the promise’s internal fulfillment handlers (like .then callbacks) until it is resumed.

The browser (Chrome, Firefox, etc.) is built with different subsystems inside the Web API layer:
--------------------------------------------------------------------------------------------------

   ~ Timer subsystem → handles setTimeout, setInterval.

   ~ Networking subsystem → handles fetch, XHR, WebSocket.

   ~ DOM event subsystem → handles addEventListener registrations for click, keydown, etc.

   ~ Other APIs → Geolocation, IndexedDB, etc.

call back queue
----------------

why we need call back queue ?
    ->if no ccall back queue and we take it directly form subsystem then below scenario
    supporse if a click event and set timeout event is both there and if i click the click event continuosly then the click event execute next after next the timer event wont have its chance 
    thus call back queue is there so everything gets its chance

    -> The Callback Queue ensures fair scheduling so that all subsystems’ callbacks (click, timeout, network, etc.) eventually get executed.
